# 7.8.1 ↔ 7.12.3 대조 결과

목적: 이 플러그인은 **7.8.1 로 컴파일해 7.12.3 운영 서버에 올린다**.
그 가정이 성립하는지를 가정이 아니라 실측으로 확인한다.

측정일: 2026-09-14 (v1.0.0)

## 두 레버를 구분한다

7.12.3 을 향한 검사는 **둘**이고 서로 대체하지 않는다.

| | 컴파일 API 검사 | 런타임 검사 (이 문서) |
|---|---|---|
| 명령 | `atlas-mvn compile -Dconfluence.version=7.12.3` | `atlas-run -Pconf7123` |
| 답하는 질문 | 7.12.3 에 이 API 가 아직 있나 | 7.8.1 로 빌드한 jar 이 7.12.3 에서 도나 |
| 결과 | 통과 (실측 19번) | 이 문서 |

`conf7123` 프로필은 `confluence.runtime.version` 만 올린다. 컴파일 축은 그대로다:

```
$ atlas-mvn -Pconf7123 dependency:list | grep 'confluence:confluence:'
[INFO]    com.atlassian.confluence:confluence:jar:7.8.1:provided
```

**이게 확인되지 않으면 이 대조는 무의미하다** — 7.12.3 으로 컴파일한 jar 을 7.12.3 에서
돌리는 시험이 되기 때문이다.

## 환경

두 환경을 함께 쓴다. 어느 하나가 다른 하나를 대체하지 않는다.

| | docker 7.8.1 | atlas-run 7.12.3 |
|---|---|---|
| 기동 | 상시 (직접 띄운 docker) | `sleep infinity \| atlas-run -Pconf7123` |
| 주소 | 환경변수 | `localhost:1990/confluence` |
| 계정 | `CONFLUENCE_USER` / `CONFLUENCE_PASS` | admin / admin (AMPS 기본값) |
| DB | **PostgreSQL 11** (운영과 같은 계열) | **H2 1.4.200** |
| 라이선스 | 직접 준비 | AMPS timebomb (자동) |
| 웹수도 | 켜짐 | **AMPS 가 인스턴스 전체에서 끔** (아래 7번) |
| 규모 | 첨부 2,046 · 본문 108 | 첨부 33 · 본문 25 |
| 덮는 축 | PostgreSQL 방언 · 웹수도 · 규모 | 상위 버전 API · SQL 이식성 · sitemesh |

기동 105초. 오프라인(`-o`)으로는 안 된다 — `com.atlassian.synchrony:synchrony-proxy:war:6.0.1`
이 로컬 저장소에 없어 `atlas-run -o` 가 실패한다. 최초 1회는 온라인이 필요하다.

### web-item 위치 — weight 200 은 "맨 아래"가 아니다

`atlassian-plugin.xml` 은 weight 200 이면 Configuration 절 맨 아래라고 적고 있었지만
실제로는 아니다. Office Connector 와 WebDAV Configuration 이 더 높은 weight 를 가진
내장 플러그인이라 우리 항목 **뒤**에 온다. 내장 Confluence 항목들 뒤·다른 플러그인
항목들 앞이다. **두 버전에서 상대 위치가 같다**는 것이 이 항목의 결과이고, weight 를
더 올려 쫓을 이유는 없다.

### 라벨 판정 (핵심)

두 인스턴스에 같은 픽스처를 심고 **비교를 위해 설정을 맞춘 뒤**(`scanHistory=true`,
`duplicateMode=FULL` — 둘 다 기본값이 아니다) 나란히 비교했다. 측정 후 docker 쪽은
기본값으로 되돌렸다. `bulk-*` 은 docker 에만 있는 성능 측정용이라
제외했다.

| 파일 | 7.8.1 | 7.12.3 |
|---|---|---|
| `spec.xlsx` | active | **active** |
| `shared.png` | risky (교차 참조) | **risky** |
| `hist.png` | history | **history** |
| `orphan.png` | orphan | **orphan** |
| `in-comment.png` | active (댓글) | **active** |
| `nested.png` | active (엔티티·중첩 매크로) | **active** |
| `blog.png` | active (블로그) | **active** |
| `dup-a.bin` / `dup-b.bin` | orphan + [중복] | **동일** |
| `same-size-a.bin` / `same-size-b.bin` | orphan, 중복 아님 | **동일** (1단계 오탐 걸러짐) |
| `big.bin` | orphan | **orphan** |
| `한글 이름.png` | orphan | **orphan** |

**13건 전부 같다.** 여기에는 이 앱에서 가장 깊은 의존이 다 들어 있다 —
`ri:attachment` 트리 순회, 교차 스페이스 참조 해소, wiki 형식 스페이스 설명,
HTML 엔티티 치환, 댓글 소유자 판정, 과거 버전 본문, 2단계 중복 판정.

근거 **건수** 만 두 건 다르다(`hist.png` ref4↔ref1, `spec.xlsx` ref4↔ref1). 원인은
버전이 아니라 **픽스처 이력 차이**다 — docker 는 픽스처를 여러 번 돌려 `spec.xlsx`
버전이 16개(atlas-run 은 4개)이고 페이지 과거 버전도 그만큼 많다(본문 108 대 25).
같은 이유로 docker 쪽만 [구버전 다량] 배지가 붙는다(임계 5, docker 15 · atlas-run 3).

## 조치한 것

**없다.** 회귀가 나오지 않았다. 코드 변경 없이 `pom.xml` 에 검증 전용 프로필
`conf7123` 만 추가했다(컴파일 축은 7.8.1 고정).

## 확인 못 한 것 — 이 실행으로 알 수 없는 것

정직하게 적는다. 아래는 **7.12.3 에서 확인되지 않았다.**

- **웹수도.** AMPS 가 인스턴스 전체에서 끄기 때문에 우리 `WebSudoManager` 호출이
  7.12.3 에서 실제로 막는지는 이 환경으로 알 수 없다. 다만 Confluence 자기 관리 화면도
  똑같이 200 이므로 **우리 앱만 다르게 동작하는 것은 아니다.** 7.8.1 에서는 우리 화면과
  Confluence 화면이 함께 302 다.
- **PostgreSQL + 7.12.3 조합.** 여기서 확인한 SQL 이식성은 H2 축이다. 운영은 Postgres 이고
  Postgres 축은 7.8.1 에서만 확인했다. 두 축이 각각 통과했다는 것이지 교차 확인이 아니다.
- **규모.** 33건짜리 인스턴스다. 성능·메모리는 이 실행이 아무것도 말해 주지 않는다
  (로드맵 2번의 주제다).
- **DC 클러스터.** 단일 노드다. (2026-09-14 추가분: 클러스터 잠금은 그 뒤에 넣었고
  두 버전 모두에서 앱이 활성화되고 동시 스캔이 202/409/409 로 갈린다 — 실측 35번.
  그래도 **노드 두 대의 실제 경합은 여기서 못 본다.**)

## 부수 관찰

- AMPS 의 `generate-rest-docs` 골이 `rest` 패키지만 javadoc 으로 훑으면서
  `package co.bskim.confluence.attachjanitor.ao does not exist` 를 30건 경고로 낸다.
  **컴파일 오류가 아니다** — 같은 로그에서 `maven-compiler-plugin` 은
  "Nothing to compile - all classes are up to date" 이고 플러그인은 정상 기동한다.
  javadoc 골의 클래스패스가 좁아서 나는 소음이다.
- `atlas-run` 은 플러그인을 `Installed: bundled` · `userInstalled: false` 로 설치한다.
  `deploy.sh` 를 이 인스턴스에 쓰지 말 것 — AMPS 가 이미 설치·활성화한다. 그리고
  **UPM "Manage apps" 표현(아이콘 · 설명 · 사용자 설치 목록)은 이 환경에서 확인되지
  않는다** — 시스템 앱으로 잡히기 때문이다. 그쪽은 docker 인스턴스가 근거다.

## 결론

**"7.8.1 로 컴파일해 7.12.3 에 올린다"는 가정이 성립한다.**

대조 22항목 중 20개 같음, 1개 환경 차이로 측정 불가(웹수도), 1개 픽스처 이력 차이.
라벨 판정은 13/13 일치한다. 코드 수정이 필요한 회귀는 나오지 않았다.

**2026-09-14 추가 대조(클러스터 잠금).** 이 문서를 쓴 뒤에 `WorkLock` 을 넣었고, 그
새 OSGi 임포트(`com.atlassian.beehive`)와 잠금 동작을 두 버전에서 다시 맞춰 봤다 —
앱 활성화 · 동시 스캔 202/409/409 · 끝난 뒤 재시작 202 · 잠금 관련 로그 오류 없음이
모두 같았다. 표는 실측 35번에 있다.

단, 위 "확인 못 한 것" 넷은 그대로 열려 있다. 특히 **Postgres × 7.12.3 조합은 아무도
확인하지 않았다** — 이 문서를 근거로 "운영에서 문제없다"고 말하면 그건 이 문서가 말한
것보다 더 말하는 것이다.
